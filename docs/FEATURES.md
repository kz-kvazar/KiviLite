# Внутреннее устройство, фичи и метрики

## Архитектура

Четыре класса, никаких библиотек, ни одной XML-разметки — весь интерфейс строится кодом.

| Класс | Строк | Назначение |
|---|---|---|
| `MainActivity` | 1 745 | Главный экран: шапка, шесть плиток, сетка приложений, режим «Изменить» |
| `PicturePanelActivity` | 478 | Панель изображения поверх любого экрана (вендорский API через отражение) |
| `ApiProbeActivity` | 229 | Разовый зонд: выгружает список методов вендорского API в `/sdcard/minihome_api.txt` |
| `SourceKeyService` | 132 | Служба доступности: перехват кнопки SOURCE (код 255) |

Все рисованные элементы — вложенные классы `View`/`Drawable` внутри `MainActivity`:

- `BgDrawable` — фон: градиенты, «занавесы», кэш в ¼ разрешения (`Bitmap` размером `w/4 × h/4`,
  на экран растягивается готовое изображение);
- `TileIcon` — иконки плиток (телевизор, надпись HDMI, шестерёнка, робот Android,
  картинка с ползунками, флешка);
- `NetIcon` — RJ45 / дуги Wi-Fi / перечёркнутый круг;
- `WeatherIcon` — значок погоды;
- `CoinIcon` — иконки валют (доллар, евро, биткоин буквой «B» со штрихами, ромб Ethereum);
- `AppAdapter` — сетка приложений с кэшем подписей и иконок.

## Что обновляется и когда

| Элемент | Период | Детали |
|---|---|---|
| Часы и дата | раз в 60 с | `Handler`-тикер, `removeCallbacks` в `onPause` |
| Значок сети | раз в 60 с | определение по `NetworkInterface`: `eth*` → RJ45, `wlan*` → Wi-Fi |
| Погода | TTL 1 ч | `ipwho.is` (координаты) + `api.open-meteo.com` (температура, код явления) |
| Курсы | TTL 3,5 ч | `open.er-api.com` (USD→UAH, EUR→UAH) + `api.coingecko.com` (BTC, ETH в USD) |
| Список приложений | по изменению набора | подписи и иконки кэшируются, повторный перебор только при смене набора |

Сетевые запросы идут с таймаутом 5 с; при ошибке остаётся последнее значение — лаунчер
никогда не показывает пустое место вместо погоды или курса.

## Режим «Изменить» и скрытые приложения

- Кнопка «Изменить / Змінити / Edit» рядом с заголовком раздела «Приложения».
- В режиме изменения карточки получают цветную рамку, а ОК открывает меню приложения
  вместо запуска: **удалить** (системный диалог `ACTION_DELETE`), **скрыть**, а для
  скрытого — **вернуть на главный экран**.
- Скрытые хранятся в `SharedPreferences` (`minihome` → ключ `hidden`, набор пакетов),
  поэтому переживают перезагрузку.
- Чип «Скрытые: N» и меню скрытых позволяют вернуть приложение, не заходя в каждую карточку.
- Выход из режима — «Готово», BACK или MENU.

Почему так: на этом пульте **удержание ОК не всегда доходит до приложения** — вендорский
слой (сервер пульта) может перехватить удержание. Режим «Изменить» — гарантированный путь,
не зависящий от того, как прошивка обходится с долгим нажатием. Удержание ОК тоже
поддержано (таймер 650 мс в `OnKeyListener` карточки + `setOnItemLongClickListener` сетки).

## Панель изображения (кнопка SOURCE)

- Служба доступности объявлена с `android:canRequestFilterKeyEvents="true"` и
  `flagRequestFilterKeyEvents`, поэтому видит нажатия раньше приложений.
- SOURCE приходит как код 255; служба поднимает `PicturePanelActivity` (полупрозрачная тема).
- Значения применяются через отражение к `com.mstar.android.tvapi.common.PictureManager`:
  подсветка (backlight) читается и пишется по-настоящему, остальные (яркость, контрастность,
  насыщенность, резкость, оттенок) хранятся в памяти панели.
- `ApiProbeActivity` — вспомогательный зонд: `am start -n com.minihome.tv/.ApiProbeActivity`
  выгружает реальные сигнатуры вендорского API в `/sdcard/minihome_api.txt`, чтобы писать
  панель по фактам, а не по догадкам.

## Метрики и как их измерять

```bash
# размер и состав APK
ls -l MiniHome.apk
# память лаунчера
adb shell "dumpsys meminfo com.minihome.tv | head -20"
# процесс и RSS
adb shell "ps | grep minihome"
# CPU (лаунчер в списке не появляется — значит простаивает)
adb shell "dumpsys cpuinfo | head -12"
# свободная память системы
adb shell "dumpsys meminfo | grep -e 'Total RAM' -e 'Free RAM'"
```

Измерено на LG 43UK32G (Android 6.0.1, 1,5 ГБ RAM):

| Метрика | KiviLite | Вендорский `com.kivi.launcher_v2` |
|---|---|---|
| Размер APK | 49 621 Б | — |
| PSS | ≈ 11,8 МБ | — |
| RSS | ≈ 42 МБ | ≈ 90 МБ |
| CPU в простое | ≈ 0% | — |
| Свободная память после подмены | ≈ 253 МБ (старт сессии: ≈ 45 МБ) | — |

## Грабли и решения (проверено на железе)

1. **`GridView` не отдаёт долгое нажатие карточке.** `OnLongClickListener` карточки не
   вызывается: `AdapterView` обрабатывает удержание сам. Решение — `setOnItemLongClickListener`
   сетки **плюс** собственный таймер в `OnKeyListener` карточки (схема на любое `ACTION_DOWN`,
   меню через 650 мс, подавление клика на `ACTION_UP`). Проверять `repeatCount == 0` нельзя:
   на этом боксе повторы приходят с `repeatCount = 1`.
2. **Подсветка «иногда полупрозрачная, иногда голубая».** `GridView` помечает элемент
   состоянием `selected`, а не `focused`; в `StateListDrawable` и `ColorStateList` должен быть
   **оба** состояния, иначе элемент выглядит невыделенным.
3. **Focusable-дети ломают `OnItemClickListener`.** Если карточка фокусируемая, клик по ОК
   уходит ей, а не `AdapterView`. Клик вешается на саму карточку в `getView()`.
4. **Заставка загрузки не гаснет** без `service.launcher.visible=1` (см. `INSTALL.md`, шаг 4).
5. **`adb pull` требует нативный путь** (`C:/...`); POSIX-путь `/c/...` даёт «cannot create file».
6. **Проверка интерфейса без «глаз»**: `uiautomator dump` даёт тексты и границы элементов,
   `screencap` + разбор пикселей — цвет подсветки и форму нарисованных иконок (например,
   значок RJ45: корпус, защёлка, восемь контактов, хвост кабеля).
7. **Кэш фона обязателен.** Пересчёт градиентов на каждом кадре на слабом SoC заметен глазом;
   в ¼ разрешения фон выглядит так же, а стоит копейки.

## Чего в лаунчере сознательно нет

- Никаких фоновых служб, аккаунтов, аналитики и рекламы.
- Никаких сетевых запросов, кроме погоды и курсов (и те — раз в час и раз в 3,5 часа).
- Ни одного изображения в APK: это и есть причина размера в 49 КБ и нулевого CPU в простое.
